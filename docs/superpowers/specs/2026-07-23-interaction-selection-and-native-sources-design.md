# FADT 交互选择与原生数据源设计（历史记录）

**日期：** 2026-07-23
**状态：** 部分方案已被后续需求替代
**范围：** 截图规则导入、规则表多选、数据源选择

> 注意：本文保留当时的设计决策，不代表当前产品契约。其中“Windows 原生资源管理器分开选择文件和文件夹”的方案已被后续需求替代。当前实现是 FADT 内置的混合数据源选择器：同一窗口可选择 Excel 文件和文件夹，双击文件夹进入内部，文件夹作为递归扫描源加入清单。当前行为以 `AGENTS.md`、`CONTEXT.md`、源码和测试为准。

## 目标

1. 让截图预览和 OCR 重建表格可在大尺寸工作表上可靠地浏览、缩放及选择。
2. 让规则表把「拖拽排序」与「多行选择」分开，支持高效的批量删除和批量复制。
3. 改用 Windows 原生资源管理器选择数据源，同时保持文件与文件夹混合累加、递归扫描和重复文件处理能力。

## 非目标

- 不允许修改 OCR 表格中的坐标或「目标数据」文本。
- 不改变既有汇总规则的计算语义、Excel 读取范围或 OCR 识别服务。
- 不发布 GitHub Release；本次仅实现与验证源代码。

## 已确认的交互约束

### 截图规则导入

- 点击截图预览后，焦点进入预览视口。
- 鼠标滚轮向上/向下以鼠标指针位置为中心缩放。
- 按住鼠标**中键**可以向上、下、左、右平移；左键不用于平移，右键保留系统菜单。
- 预览始终提供可拖动的水平和垂直滚动条。
- OCR 重建表格的默认视觉尺寸缩为当前的 0.5 倍（字体、行高和列宽同步缩小）。
- 在「输出列名」或「目标数据」模式拖选时保留既有选择：范围中存在已选单元格则整段反选，否则整段选中。
- 指针停在表格边缘时按方向自动滚动，滚动期间持续扩展选择范围。
- 同一行的输出列名可暂时多选；「配对填充」前每行必须恰有一个输出列名，否则明确提示冲突并阻止填充。
- 双击仅在「输出列名」模式下可编辑 OCR 文本，必须二次确认；坐标始终不可改，「目标数据」模式下任何文本都不可改。

### 规则配置表

- 六点拖拽手柄是唯一可改变行顺序的触发区域。
- 非输入控件区域可点击、Ctrl+点击或拖动跨行选择/反选；触及列表上、下边缘时自动滚动并继续选择。
- 输入框或下拉框获得焦点时只进行原有编辑，不触发行多选。
- 每行复选框和表头全选框与同一选择集同步。
- 删除选中规则支持批量删除；无选择时保留现有单条删除行为或提示无可删项（二者以后者为准）。
- 选中多条规则后点击「新增规则」将其按当前顺序复制，插入最后一条源规则之后；原规则保留；复制出的新规则变为当前选中项，原选择清除。无选择时新增一条空规则。

### 数据源配置

- 使用 Windows 原生资源管理器，而不再使用自定义文件浏览器。
- 原生对话框不能在同一窗口混选文件与文件夹，因此提供「添加 Excel 文件」和「添加文件夹」两个入口；每次结果追加到同一个混合数据源清单。
- 文件入口支持多选 `.xlsx`、`.xlsm`、`.xltx`、`.xltm`；文件夹入口支持多选目录，目录会递归扫描其子目录。
- 加入清单前解析所选文件和目录中的实际 Excel 文件，并按规范化绝对路径（Windows 不区分大小写）检测重复。不会按文件名或内容哈希误判。
- 发现重复时提供「自动去重 / 保留重复 / 返回修改」。自动去重保证后续任务执行时每个规范化文件路径只处理一次；保留重复则维持源清单语义。

## 方案 A：在现有组件上增量改造

### 1. 截图预览视口

在 `RuleImageImporter.vue` 内将静态 `<img>` 容器替换为独立的 `ImageViewport` 逻辑（可先作为同文件的组合式状态，不增加不必要的组件边界）：

- 状态：`zoom`、`panX`、`panY`、中键拖动起点、视口元素引用。
- 缩放：限制在安全区间（建议 25%–400%），按鼠标相对内容坐标修正滚动位置，确保指针下内容不会跳动。
- 平移：`pointerdown` 仅处理中键；用 Pointer Capture 在窗口外释放时清理状态；通过 `scrollLeft/scrollTop` 实现二维平移。
- 可访问性：预览容器带 `tabindex="0"`、焦点样式与说明文本；不拦截右键菜单。
- CSS：固定为 `overflow: scroll`，以便水平、垂直条始终存在；实际图像尺寸由缩放值决定而非 `object-fit` 裁剪。

### 2. OCR 表格选择模型

在 `ruleImageSelection.ts` 中补充以集合为中心的范围切换函数，而不再每次拖动覆盖旧集合：

1. 计算起止坐标构成的矩形候选集合。
2. 若矩形与当前集合有交集，则逐项切换矩形中的单元格；否则将矩形中的单元格并入集合。
3. 输出列名使用同一逻辑，不清除同一行其他选择；目标数据同样可多选。
4. `buildRowSelectionPairs` 改为先验证每个参与行的输出列名数量恰为 1；违规时返回可读的冲突行列表而非隐式取最后一个。

表格 DOM 以一个可滚动容器承载。拖选开始时记录锚点；在 `pointermove` 和边缘自动滚动的动画帧中用当前命中单元格更新临时范围。滚动在指针离开边缘或指针释放时停止。缩小后的网格以统一 CSS 变量定义：列宽、行高、主文字和坐标文字均为既有基准的 50%。

双击编辑遵循：仅 `selectionTarget === 'output'` 时弹出确认输入框；确认后将修订文字保存在 OCR 单元格的显示覆盖层（坐标 ID 不变）。「目标数据」模式忽略双击编辑。

### 3. 规则表选择与排序解耦

`App.vue` 采用 `selectedRuleIds: Set<string>` 取代单一 `selectedRuleIndex`；规则数据补充稳定 `id`（首次加载旧方案时迁移生成）。

- 排序：仅拖拽手柄注册排序 Pointer 事件，排序完成后依据 ID 重新计算集合，避免索引变化导致选错行。
- 单击：非控件行区域点击决定主选中行；Ctrl 点击切换该行；点击已选单行可取消。
- 范围拖选：根据起止行 ID 生成连续行集合；与既有集合相交则逐项反选，否则并入；边缘滚动由表体容器完成。
- 表头：全选框只作用于当前可见规则行；半选状态由已选数量推导。
- 批量操作：删除前用规则 ID 快照，再一次性过滤；复制按原行顺序深拷贝、生成新 ID，并插入最后一个被选中源规则之后。
- 行内 `input/select/button` 通过事件边界阻止选择手势，保留正常编辑、点击和下拉交互。

### 4. 原生数据源选择和去重

在 `App.vue` 使用已安装的 Tauri Dialog 插件：

- `open({ multiple: true, filters: [...] })`：添加 Excel 文件。
- `open({ directory: true, multiple: true })`：添加文件夹。
- 用户可反复使用两个入口，结果追加至当前 `targetPaths`。

新增后端只读预检命令（放在既有文件扫描模块附近），接收候选源路径和当前源路径，递归枚举支持扩展名的文件，返回：规范化路径、来源路径、重复组与不可访问路径。实际执行阶段共享同一规范化/去重策略，避免 UI 与任务运行结果不一致。

前端收到预检结果后：无重复即合并；有重复即展示三选一确认。自动去重时保留能够覆盖唯一文件集合的源项，并把重复文件排除集写入方案；保留重复时不写排除集；返回修改不改变清单。方案序列化加入可选字段，保证旧方案仍可直接加载。

## 失败与边界处理

- 非法或无权限目录：列为不可访问项，提示用户；其余有效源可继续加入。
- 空文件夹：可以保留为源，但显示「未发现可支持的 Excel 文件」。
- 双击输出列名时为空：禁止确认并提示需要非空文本。
- 自动滚动速度按距边缘距离线性提高，并设置上限，防止高速闪动。
- 用户切换图片、关闭对话框或失焦：停止所有 Pointer Capture 和动画帧，避免残留拖动状态。

## 测试与验收

### 单元测试

- 范围追加、范围反选、同一行输出列名冲突、有效配对。
- 规则多选的单击/Ctrl/范围切换、批量删除、批量复制插入顺序。
- 路径规范化、文件夹与直接文件重叠、大小写差异、重复保留/去重策略。

### 组件/手工验收

1. 预览在 25%–400% 缩放时，滚轮锚点、中键全向平移、两条滚动条均正常。
2. 表格以半尺寸显示；拖选保留既有结果，边缘四向自动滚动，双击仅能修改输出列名并有确认。
3. 六点排序不受多选影响；其他行区域多选、控件内编辑、全选、批量删除和复制均正确。
4. 两类原生对话框可多选并累计；文件夹递归扫描，重复提示与三种决策的执行结果一致。
5. 运行现有 `npm.cmd test -- --run`、`npm.cmd run typecheck`、`npm.cmd run build`，并在需要时运行 `cargo test`/`cargo check`。
